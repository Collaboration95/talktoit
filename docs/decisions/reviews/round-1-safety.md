FINDINGS:

- [P2] F1 — `backend/app/llm/orchestrator.py:314–316,386–388` and `backend/app/api/chat.py:537–542`, with resource teardown at `backend/app/db/connection.py:104–114`: cancellation can close a connection and release its generation lease while dispatched work still uses it. `asyncio.to_thread` keeps running after its await is cancelled. The API drains only `_prepare_chat`; it does not drain the orchestrator's dispatch worker. Deterministic reproduction: import the committed synthetic fixture, pause the real `_dispatch_tool` immediately before its DB access, cancel the HTTP chat task, then perform confirmed health deletion before releasing the worker. Cancellation returns while the worker is paused; `generation_is_leased` is false; deletion returns 200 and removes the DB; the resumed worker raises `ConnectionException: Connection Error: Connection already closed!`. This contradicts #160/#161/#162's reader-lifetime guarantee. Smallest fix: shield and drain every connection-consuming worker before propagating cancellation and leaving its snapshot context, including both dispatch branches and standalone profile work. Shielding without draining is insufficient. Add a barrier regression through the actual orchestrator and HTTP dependency, asserting deletion stays deferred and the connection remains usable until worker exit. Reproducer: `/tmp/tti-final-20261023/reviews/safety-run/repro_cancelled_dispatch.py`; observed output: `repro-cancelled-dispatch.log` alongside it.
- [P2] F2 — `backend/app/db/dataset_lifecycle.py:492–510,567–585` and `backend/app/db/connection.py:110–114`: successful ordinary imports do not retire old generations when their readers finished before supersession. Replacing `retained.json` makes its former generation eligible, but publication/recovery never attempts that retirement. The sole production call to `retire_generation` is snapshot teardown, which returns immediately if that snapshot's generation is still active. Four sequential official imports, each followed by a completed snapshot and then two recoveries, leave four complete databases; only active/newest rollback are protected, and both older copies have no leases. Repeated normal imports therefore retain another full health DB indefinitely and can exhaust local storage. These are previously committed copies, not intentionally preserved ambiguous crash artifacts. Smallest fix: under the writer protocol, retain the prior retained pointer as a proven retirement candidate when replacing it, then attempt/retry exclusive-lease retirement after successful reconciliation; preserve current/rollback/leased/unknown contents. Add sequential-import and release-during-publication regressions. Reproducer: `/tmp/tti-final-20261023/reviews/safety-run/repro_idle_retention.py`; observed output: `repro-idle-retention.log` alongside it.
