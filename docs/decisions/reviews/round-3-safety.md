- [P2] R3-F1 — `backend/app/db/dataset_lifecycle.py:735–739` (`_remove_generation`; shared by retirement and explicit deletion). The code stats a child name, compares it with the open file descriptor, then unlinks that name. `dir_fd` binds the parent directory, not the child inode. A replacement between the comparison and `os.unlink` is deleted although neither its bytes nor its inode was validated.

  Four deterministic current-source tests cover DB and manifest replacement under retirement and explicit deletion. At entry to the actual `os.unlink` call, after the final stat/fstat comparison, rename the validated file aside and install a new regular file containing an unrelated sentinel. In all four cases the replacement is deleted and the original survives outside the allocation. Retirement prunes its candidate; explicit deletion clears its intent and returns success, with inactivity correctly committed. Active C/root remains coherent in retirement. This is replacement of a directory entry, not an in-place write to the open immutable file; no import-only race or active-generation loss is claimed.

  Minimum correction: ensure the destructive operation cannot consume an unvalidated replacement entry. A portable detach/quarantine-and-validate protocol, with conservative preservation on mismatch, is one option; merely adding another pre-unlink stat leaves the same gap. Preserve persisted authority on mismatch, return inactive retryable conflict for explicit deletion, and retain existing lease/fsync/partial-cleanup guarantees. Regress both file names and both callers at the final check/unlink seam. Reproducer: `round-3-safety-run/test_review_ownership.py`; observations: `file-swap-*.json` alongside it.

Replacing that directory after the last validation makes rmtree open and recursively delete the replacement. Three recoveries complete without preserving the replacement. This reproduces the original directory-ownership race in the adjacent artifact layer, which is unchanged since the original integrated candidate.

  Minimum correction: compare the persisted identity against the opened allocation after acquiring cleanup authority, and keep all destructive operations bound to that validated directory. Avoid a final pathname rmtree/rmdir that can target a replacement; retain empty allocation metadata if portable conditional removal is unavailable. Preserve changed/unknown contents and durable proof. Add replacement barriers for artifact cleanup, including the configured-root shard case reproduced here.
