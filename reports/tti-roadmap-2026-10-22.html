Three additional synthetic checks reproduced gaps: a configured shard folder loses unrelated files; a forced exit during replacement can leave the active database path missing; and a CLI database override can return another database’s cached answer. These deserve the first fixes.

The next steps, in order

  1. Start with a small safety and maintenance batch.

    Protect configured folders, isolate CLI caches, and repair the failing dependency audits. Reconcile old tickets with code that has already been fixed.

  2. Make interrupted imports recoverable.

    Keep the database and its dataset identity in sync through cancellation, restart and concurrent requests. This is the main stability milestone.

  3. Make the existing app easier to use.

    Add visible date controls, keep filters available when results are empty, guide the first import, and explain chat limitations accurately.

  4. Measure and improve speed, then add analytics.

    Reduce the initial chart bundle and repeated work. Move large trend aggregation into DuckDB if benchmarks confirm the benefit. Then add sleep questions and health-metric comparisons.

Round 1 · highest priority

Trust imports and dataset identity

9–18 days, split into PRs

Outcome: re-importing or cancelling cannot strand the app or mix answers from different datasets.

  • Quick fixes: create owned shard subdirectories; isolate unmatched CLI database overrides from shared caches. About 2–4 days together.
  • Recoverable activation: use a recovery journal or immutable dataset files with a transactional active pointer. About 3–6 days.

Done when: forced termination at every activation boundary recovers a matching database/manifest; sentinel files survive; two databases never share answers; concurrent import/chat/dashboard/delete tests stay consistent; abandoned owned artifacts are recoverable or removed.

3. CLI database overrides can replay the wrong cached answer

Dataset A’s answer was cached. The same question then targeted synthetic database B with a different known duration. Local-model startup and gateway creation were stubbed; the CLI cache path itself ran.

Observed: B contained a 999-minute workout; the CLI returned A’s 45.5-minute answer with provenance cached.

Source: CLI database and cache identity

4. Dataset connection and manifest can be acquired separately

Requests can retain a connection to the previous database while independently reading the newly active dataset identity. A generation-bound snapshot would prevent incorrect provenance or cache identity during replacement.

A concurrency risk traced through source; no runtime mislabelling was reproduced in this review.

5. There are concrete opportunities to remove work

  • Initial JS: production entry chunk is 1,377.60 kB minified / 456.41 kB gzip. This is build size, not measured load time.
  • Trends: matching observations are fetched and bucketed in Python; large ranges can increase memory and transfer.
